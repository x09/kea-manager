# kea-manager

Редактор конфигурации служб **kea-dhcp4** и **kea-dhcp6** (Kea DHCP) в стиле
оснастки Microsoft DHCP. Слева — дерево «Сервер → IPv4 / IPv6 → подсети»,
справа — панель редактирования выбранного узла.

Целевая версия Kea: **3.2.0**. Служба `kea-dhcp-ddns` (d2) в этой версии
не настраивается и не поддерживается.

## Возможности

Дерево в стиле MS DHCP с иконками: `Сервер → IPv4 / IPv6 → подсети`, а под
каждой подсетью — узлы `Пулы`, `Резервирования`, `DHCP-опции`; под службой —
`Глобальные DHCP-опции`. Если DHCPv6 не сконфигурирован, его узел помечается
иконкой «не сконфигурировано», и файл `kea-dhcp6.conf` не создаётся.

Ядро:

- Создание и удаление подсетей (`subnet4` / `subnet6`), задание CIDR и `id`.
- Управление пулами адресов внутри подсети (диапазон `A - B` или `A/prefix`)
  с проверкой принадлежности подсети.
- Общие настройки службы: время аренды (`valid-lifetime`), таймеры
  `renew-timer` / `rebind-timer`, список интерфейсов.
- Загрузка и сохранение `kea-dhcp4.conf` / `kea-dhcp6.conf`.

Резервирования (`reservations`):

- Закрепление статических адресов за устройствами: `hw-address` (MAC),
  `ip-address`, `hostname`. Проверка MAC и принадлежности адреса подсети.

DHCP-опции (`option-data`):

- Опции на уровне службы (глобально) и на уровне подсети.
- Каталог известных опций с проверкой формата: `routers`,
  `domain-name-servers`, `domain-name`, `domain-search`,
  `classless-static-route`, `time-servers` (для IPv6 — `dns-servers`,
  `domain-search`, `sntp-servers`), плюс ввод произвольной опции.

Мониторинг и управление арендами:

- Узел «Аренды» под каждой службой. Чтение файла аренд memfile
  (`kea-leases4.csv` / `kea-leases6.csv`) с дедупликацией «побеждает
  последняя запись», объединением LFC-файлов (`.2`) и исключением
  удалённых аренд (`valid_lifetime = 0`). Путь берётся из
  `lease-database.name`, переопределяется вручную.
- Таблица: адрес, MAC/DUID, имя хоста, время истечения, остаток,
  состояние. Опциональный показ неактивных (отклонённых/освобождённых).
- Принудительное удаление аренды через unix control-socket командой
  `lease4-del` / `lease6-del` — с обязательным подтверждением. Путь сокета
  берётся из `control-socket` / `control-sockets`.

  Важно: удаление требует загруженной в Kea hook-библиотеки
  `libdhcp_lease_cmds`. Если она не подключена, сервер вернёт ошибку
  «команда не поддерживается».

Высокая доступность (HA):

- Узел «Высокая доступность (HA)» под каждой службой. Включение создаёт
  запись `libdhcp_ha.so` в `hooks-libraries` (прочие hook-библиотеки не
  затрагиваются). Три режима: `load-balancing`, `hot-standby`,
  `passive-backup`.
- Задание `this-server-name` и таблицы партнёров (`peers`): имя, URL,
  роль, `auto-failover`. Проверка допустимости ролей под выбранный режим
  и корректности URL.

  Важно: для обмена арендами HA также требует библиотеки
  `libdhcp_lease_cmds`.

Политики (`client-classes`):

- Узел «Классы клиентов» под каждой службой. Создание классов с именем и
  `test`-выражением (напр. `option[60].text == 'CiscoIPPhone'`),
  редактирование `option-data` внутри класса.
- Привязка класса к пулу через поле `client-class` в диалоге пула.

Мультисерверный режим:

Верхний уровень дерева — список серверов, сохранённый в
`~/.config/kea-manager/kea-manager.ini` и подгружаемый при запуске.
Каждый сервер — это либо API-подключение, либо локальный каталог.

- «Файл → Добавить сервер (API)…» или «Добавить сервер (каталог)…» —
  добавляет запись в список (запрашивается имя сервера).
- Двойной клик по узлу сервера — подключение: активный сервер
  раскрывается в дерево служб IPv4/IPv6. Для API запрашивается пароль
  (в файле не хранится).
- Правый клик по серверу — «Подключиться», «Изменить…», «Удалить сервер».
- Одновременно активен один сервер; при переключении, если есть
  несохранённые изменения, выводится предупреждение.

Два типа серверов (бэкенды):

- **Локальный каталог (файлы)** — чтение/запись `kea-dhcp4.conf` /
  `kea-dhcp6.conf` на диске. Работает даже при остановленной службе,
  сохраняет неизвестные ключи round-trip.
- **API** — управление живым сервером Kea по control-channel (HTTP/HTTPS)
  с базовой аутентификацией. В Kea 3.2.0 DHCP-серверы принимают команды
  напрямую, отдельный `kea-ctrl-agent` не нужен.

В API-режиме:

- Загрузка конфигурации командой `config-get`; каждая служба
  (DHCPv4/DHCPv6) — отдельный HTTP-эндпоинт (разные адрес/порт).
- «Сохранить» выполняет `config-test` → `config-set` → `config-write`:
  проверка, применение в память без перезапуска и запись на диск сервера.
- Аренды читаются командами `lease4-get-page` / `lease6-get-page`
  (постранично), удаление — `lease4-del` / `lease6-del`.

  Ограничения API-режима: `config-get` не возвращает комментарии;
  требуется запущённый сервер и настроенный HTTP control-socket; для
  удалённого доступа рекомендуется HTTPS.

### Round-trip загрузки

Редактор сохраняет **все** ключи исходного файла, даже те, которые он пока
не умеет редактировать (`control-socket`, `lease-database`, `hooks-libraries`
и т.д.). При перезаписи эти секции остаются нетронутыми.

Парсер понимает комментарии Kea (`//`, `#`, `/* */`) и висящие запятые.
Ограничение: сами тексты комментариев при перезаписи в JSON не сохраняются.

### Применение изменений

Редактор **только пишет** файлы конфигурации. Перезагрузку служб выполняйте
вручную, например:

```
systemctl reload kea-dhcp4     # или restart
systemctl reload kea-dhcp6
```

## Язык интерфейса (i18n)

Поддерживаются русский и английский, переключение — меню «Язык». Выбранный
язык сохраняется в `~/.config/kea-manager/kea-manager.ini` и применяется при
следующем запуске (смена языка — через перезапуск, стандартный подход
gettext).

Технология — gettext, домен `kea-manager`. Исходные строки (msgid) на
русском; для английского используется скомпилированный каталог
`locale/en/LC_MESSAGES/kea-manager.mo`. Файлы перевода ищутся в нескольких
каталогах по приоритету:

```
<пакет>/locale                     (в поставке)
/usr/share/kea-manager/locale      (системный)
/usr/share/locale                  (общесистемный)
```

Пересборка перевода без gettext-utils (чистый Python):

```
python3 tools/make_en_po.py      # обновить en .po из строк в коде
python3 tools/pocompile.py --all # скомпилировать все .po -> .mo
```

## Зависимости

Только стандартная библиотека Python 3 и `tkinter`. Сторонних пакетов нет.

На AltLinux установите tkinter:

```
apt-get install python3-module-tkinter
```

## Запуск

Проще всего — через лаунчер (запускается из любого каталога):

```
./kea-manager.py                 # пустой проект
./kea-manager.py /etc/kea        # загрузить conf-файлы из каталога
```

Серверы добавляются через меню «Файл → Добавить сервер…» и сохраняются в
списке; двойной клик по серверу в дереве подключает его. Каталог,
переданный в командной строке, регистрируется как файловый сервер и
подключается автоматически.

Либо как модуль:

```
python3 -m kea_manager /etc/kea
```

## Тесты

```
python3 -m unittest discover -s tests -v
```

Тесты не требуют tkinter и проверяют парсер JSONC, валидаторы и round-trip
модели конфигурации.

## Структура

```
kea-manager.py        лаунчер
kea_manager/
  __main__.py         точка входа (python3 -m kea_manager)
  model/config.py     модель round-trip (DhcpConfig, KeaProject)
  model/options.py    каталог DHCP-опций и валидация значений
  util/jsonc.py       парсер JSON с комментариями Kea
  util/validators.py  валидация IP, подсетей, пулов, MAC, таймеров
  ui/mainwindow.py    главное окно, дерево, меню
  ui/panels.py        панели (служба, подсеть, пулы, резервирования, опции)
  ui/icons.py         иконки, генерируемые в рантайме (без внешних файлов)
  ui/about.py         окно «О программе» с гиперссылкой
  model/leases.py     чтение memfile CSV (аренды)
  model/ha.py         конфигурация HA (hooks-libraries)
  model/classes.py    client-classes (политики)
  model/backend.py    бэкенды File/Api (источник конфигурации)
  util/ctrlsocket.py  клиенты control-channel: unix-сокет и HTTP(S)
  util/settings.py    настройки и список серверов (ini)
  i18n.py             инициализация gettext, поиск переводов
  ui/connect.py       диалог подключения по API
  locale/             переводы (en/.po+.mo, ru/.po)
tools/                pocompile.py (.po→.mo), make_en_po.py, wrap_i18n.py
tests/test_core.py    тесты ядра
sample/               пример конфигурации и файла аренд для проверки
```
